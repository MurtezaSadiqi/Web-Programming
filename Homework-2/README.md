  <h1>جواب سوال اول:</h1>
  تفاوت‌های اصلی نسخه‌های مختلف HTTP به این صورته:

**نسخه ۰.۹ پروتکل HTTP:** خیلی ساده بود، فقط متد GET داشت و هدر هم نداشت.

**نسخه ۱.۰ پروتکل HTTP:** هدرها، کدهای وضعیت و متدهایی مثل POST و HEAD اضافه شدن. معمولاً برای هر درخواست یک اتصال جدا ایجاد می‌شد.

**نسخه ۱.۱ پروتکل HTTP:** اتصال‌های پایدار یا Keep-Alive، قابلیت Pipelining و هدر Host اضافه شدن.

**نسخه ۲ پروتکل HTTP:** از قابلیت Multiplexing استفاده می‌کنه؛ یعنی چند درخواست می‌تونن هم‌زمان روی یک اتصال ارسال بشن. همچنین هدرها رو فشرده می‌کنه.

**نسخه ۳ پروتکل HTTP:** به‌جای پروتکل TCP از QUIC استفاده می‌کنه که روی UDP ساخته شده. این نسخه مشکل Head-of-Line Blocking رو هم در سطح اتصال TCP برطرف می‌کنه.

**چرا HTTP/3 از UDP استفاده میکند؟**

چون QUIC روی UDP پیاده‌سازی شده و امکاناتی مثل انتقال مطمئن داده‌ها، کنترل ازدحام و رمزنگاری رو خودش مدیریت می‌کنه. این کار باعث می‌شه ارتباط سریع‌تر برقرار بشه و اگه یک بسته گم بشه، بقیه جریان‌ها مجبور نباشن منتظر اون بمونن.




<h1>جواب سوال دوم:</h1>
الف) تفاوت این دو مدل

در ارتباط Stateful، سرور وضعیت قبلی کاربر رو نگه می‌داره و می‌تونه از اطلاعات درخواست‌های قبلی استفاده کنه. ولی در Stateless، هر درخواست مستقل از درخواست‌های قبلی بررسی می‌شه و سرور به‌صورت پیش‌فرض وضعیت کاربر رو بین درخواست‌ها نگه نمی‌داره.

ب) HTTP کدوم نوعه؟

پروتکل HTTP از نوع Stateless هست. یعنی مثلاً وقتی کاربر لاگین می‌کنه، خود HTTP به‌تنهایی نمی‌تونه تشخیص بده درخواست بعدی هم مربوط به همون کاربره.

برای حل این مشکل از روش‌هایی مثل Cookie، Session و Token استفاده می‌کنیم. مثلاً بعد از لاگین، سرور یک شناسه Session به کاربر می‌ده و مرورگر اون رو در درخواست‌های بعدی می‌فرسته تا سرور بتونه کاربر رو شناسایی کنه.
