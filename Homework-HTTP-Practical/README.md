# تمرین عملی HTTP — پراکسی معکوس با JWT

## سؤال اول: چطور سرویس فقط در شبکه داخلی اجرا بشه؟

برای اینکه سرویس از اینترنت مستقیم قابل دسترسی نباشه، نباید پورت اون رو روی سیستم میزبان منتشر کنیم. در این پروژه سرویس httpbin فقط داخل شبکه خصوصی Docker اجرا می‌شه و فقط پراکسی می‌تونه بهش درخواست بفرسته. برای اجرای واقعی در یک سازمان هم می‌شه سرویس رو به آدرس شبکه داخلی متصل کرد و با فایروال دسترسی خارجی رو بست. در فایل Docker Compose، سرویس httpbin فقط از `expose` استفاده می‌کنه و `ports` نداره؛ در نتیجه پورتش از بیرون منتشر نمی‌شه.

## سؤال دوم: فلسفه TLS Termination چیه؟

با TLS Termination، ارتباط رمزنگاری‌شده HTTPS در پراکسی معکوس دریافت و رمزگشایی می‌شه. به این ترتیب، سرویس قدیمی لازم نیست خودش گواهی دیجیتال یا HTTPS رو مدیریت کنه. پراکسی می‌تونه گواهی و تنظیمات امنیتی رو یکجا مدیریت کنه و درخواست رو به سرویس داخلی بفرسته. البته اگر شبکه بین پراکسی و سرویس داخلی قابل اعتماد نباشه، بهتره اون قسمت هم رمزنگاری بشه. **در این تمرین TLS Termination پیاده‌سازی نشده** و فقط مفهومش توضیح داده شده؛ چون بخش عملی استاد، JWT رو الزام کرده و ورودی پورت ۸۰ رو خواسته.

## سؤال سوم: پیاده‌سازی پراکسی با JWT

این پروژه دو سرویس داره: یک سرویس قدیمی شبیه‌سازی‌شده با httpbin و یک پراکسی Node.js. درخواست‌های ورودی به پورت ۸۰ پراکسی می‌رسن. مسیر `/login` با نام کاربری و رمز عبور، توکن JWT یک‌ساعته صادر می‌کنه. برای مسیرهای دیگه، پراکسی هدر Authorization رو بررسی می‌کنه. اگر توکن معتبر باشه درخواست رو به httpbin روی پورت داخلی ۸۰۸۰ می‌فرسته؛ در غیر این صورت کد ۴۰۱ برمی‌گردونه.

### راه‌اندازی

اول Docker Desktop رو اجرا کن. فایل `.env.example` رو به `.env` کپی کن و مقادیر محرمانه رو عوض کن. فایل `.env` نباید وارد GitHub بشه.

```bash
cp .env.example .env
# در ویندوز PowerShell به جای دستور بالا:
# Copy-Item .env.example .env
docker compose up --build -d
```

اگر پورت ۸۰ روی سیستم اشغال بود، می‌تونی موقتاً در `docker-compose.yml` مقدار `80:3000` رو به `8088:3000` تغییر بدی و در تست‌ها به‌جای پورت ۸۰ از ۸۰۸۸ استفاده کنی.

### تست در PowerShell ویندوز

بدون توکن باید خطای ۴۰۱ دریافت بشه:

```powershell
curl.exe -i http://localhost/get
```

برای گرفتن توکن، مقادیر نام کاربری و رمز عبور باید با فایل `.env` یکی باشن:

```powershell
$response = Invoke-RestMethod -Method Post -Uri http://localhost/login -ContentType 'application/json' -Body '{"username":"student","password":"change-this-password"}'
$token = $response.token
curl.exe -i -H "Authorization: Bearer $token" http://localhost/get
```

در تست دوم باید پاسخ موفق httpbin دریافت بشه. برای توقف پروژه:

```bash
docker compose down
```

### نکات امنیتی

توکن‌ها با الگوریتم HS256 امضا می‌شن و زمان انقضا دارن. مقدار محرمانه امضا از متغیر محیطی خونده می‌شه. پراکسی هدر احراز هویت رو به سرویس داخلی ارسال نمی‌کنه. این پروژه یک نمونه آموزشی هست؛ برای انتشار عمومی باید HTTPS، محدودیت تعداد تلاش‌های ورود و مدیریت امن حساب‌های کاربری هم اضافه بشه.

## استفاده از هوش مصنوعی
